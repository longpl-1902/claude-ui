## T07 - FIX
1. [R-10, sign-in completion] "Sign in again" on an account that is already signed in completes too early. When `baselineHadEmail` is true, `done` fires on any mtime bump while the old email is still present (`src/main/accounts/signIn.ts:127-128`). The CLI writes `.claude.json` at startup (the Risks section notes firstStartTime and similar), so the panel can show "Ready" before the user signs in. **Correct:** if the baseline had an email, `done` needs `exitCode === 0`, or a change where the email differs from the baseline email. If the baseline had no email, keep the current rule: an email is present and the file changed, or the process exited 0. Store the baseline email (in memory only, never logged) for the comparison. Add tests: baseline signed in, an mtime bump with the same email stays `waiting`, then exit 0 gives `done`.
2. [R-10, race] `evaluate` drops events that arrive while a previous evaluate is still in flight (`signIn.ts:121`, `if (... e.busy) return`). A watcher change, or the pty exit, that lands during the two awaits is lost. If the first read happened before the email was written, the panel waits until the user clicks Check now. **Correct:** use a `dirty` flag. When `busy`, set `dirty = true` and return. In `finally`, if `dirty`, clear it and run `evaluate(e)` again. Add a test: fire two watcher changes back to back, where the file has an email only before the second; the result is `done`.
3. [R-12/R-09, input validation] A relative config dir is accepted and stored. `displayDir` returns the trimmed text unchanged when it is not absolute (`src/main/accounts/accountsService.ts:108`), and `validProfile` and `linkDetected` (`:210`, `:244`) then save it. That profile can never launch (`launchClaude` returns a misleading `spawn-failed`, `:395`) or sign in (`invalid-folder`). **Correct:** `displayDir` returns null for a non-absolute path after `~` expansion. `saveProfile` and `linkDetected` return `{ok:false, reason:'invalid-folder'}`, and the editor shows that reason. Add a test: `saveProfile({configDir:'foo', ...})` gives `invalid-folder` and nothing is written.
4. [R-10/R-12] A finished sign-in does not refresh the snapshot. The service listens to `pty.onExit` (`:208`) but not to `signIn.onStatus`. When completion comes from the file watcher while `claude auth login` is still running, the cards and Detected logins keep showing "Not signed in" until the login process exits. **Correct:** in `createAccountsService`, subscribe `signIn.onStatus((s) => { if (s.step === 'done') void emitChanged() })`, and test that a done status emits `changed`.
5. [R-08, low] `launchClaude` runs the lock check and the spawn outside `serial` (`:386-396`). Two quick spawns for different accounts in the same folder can both pass the lock. **Correct:** run the check and the spawn in one `serial(...)` block, so the second check sees the first session.

[R-13, reattach correctness] Output is duplicated when a terminal reattaches during output. `TerminalView` subscribes to `onData`, then calls `getBuffer`, and finally replays every pushed chunk (`src/renderer/src/components/terminal/TerminalView.tsx:48-52, 89-97`). Any chunk that is in the buffer and also still in flight gets written twice, which garbles TUI redraws. This happens when toggling the pane while claude is drawing. **Correct:** keep a running byte counter per pty in `ptyManager`. `getBuffer` returns `{data, end}`, and every `pty:data` push carries `end` (its offset after the chunk). Add a terminal test where a chunk is both in the buffer and pushed before `getBuffer` resolves: it is written once.
